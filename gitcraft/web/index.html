A few things before you begin.

Run GitCraft locally

You need Python 3.10+, Git, and a modern browser. Run these in your computer’s terminal, then open the local address.

git clone https://github.com/blakc-coffee/gitcraft.git
cd gitcraft
python -S -m gitcraft.server

Open http://127.0.0.1:8765/. No GitHub login is needed inside GitCraft.

Do I need to know Git already?

No. Try a first change in the workspace for an optional starting goal. If you know the basics, go straight to branches or sharing.

Are these real Git commands?

Yes. Supported commands run native Git against disposable practice repositories. You submit every command yourself. The terminal is bounded, rather than a general shell.

Am I working with another person?

You control both your workspace and Sam’s. They are separate Git repositories, so you can explore how collaboration works without needing a second person.

Will my practice be saved?

Practice repositories last while the local server runs. Stopping it removes them. Browser drafts are not a backup of commits or staging. Undo action recovers the last playground action across all workspaces.

Does this connect to my projects?

No. The supplied bookshop project is separate from your personal repositories. External remotes and GitHub authentication are outside this version.

Keep a change of your own

Add Saturday opening hours to README.md, or choose another small text change. Aim to record that change in a commit you can find again.

What does that involve?

Save file writes your text to the working file. Staging selects the content for your next commit. Committing records that staged content locally; it does not share it with Sam.

How can I inspect it?

Use git diff for working changes, git diff --staged for your next commit, and git log --oneline to find recorded commits.

There is no required wording or score. Keep exploring, or close Help whenever you like.

What is this useful for?

Use this after a commit, push or fetch to see whose branch changed and whose files stayed local. Fetch receives history; merge combines it with a branch. Opening this panel does neither.

This is the latest state inspected by GitCraft, not a live remote check. Different commit IDs alone do not prove which branch is ahead. Browser drafts are separate from saved working files.
