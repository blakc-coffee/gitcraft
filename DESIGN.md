# GitCraft presentation: Split Workbench

The user selected the Split Workbench image and requested a tools sidebar and thinner square scrollbars. The desktop app uses a narrow tools rail, file tabs and editor on the left, and a larger persistent native-Git terminal on the right. Help, History, Files and exchange tools are disclosed from the rail. Workspace and Commands are persistent top-level navigation beside the brand. Command helpers only suggest text; Enter/Run is required. On narrow screens the editor sits above the terminal and the rail stays accessible. Terminal focus can hide the editor.

Selected source: artifacts/split-workbench-reference.png. Charcoal/zinc/ivory with muted amber actions follows that selected image; no final global restriction on later themes. Keel, Quarry and Signal Console remain earlier named references whose actual artwork was not supplied. No invented fidelity to those themes is claimed.

All app overflow uses 5px square-corner scrollbars in Chromium with theme colours; Firefox uses its native thin scrollbar styling. Forced-colour mode retains platform accessibility. System sans typography and monospace file/terminal content preserve the buildless stack. Native Git state and existing learner-authored content remain authoritative.

The main learning loop remains inspect → edit/save → diff → stage → commit → share, without gates or automatic task completion. Explanation, native output and the repository's actual state provide feedback. A site preview is optional through Files. Desktop/mobile screenshots and interaction verification are recorded in design-qa.md.

## Command reference revision — 3 November 2026

Replace the oversized introduction and all-command sidebar with a compact heading, search across the full catalog, five purpose links and a short list for the selected purpose. Selected command, purpose and global page each have distinct current-location styling. These are ordinary navigation links with native keyboard behavior, not ARIA tabs. Desktop explanations and practice examples share the available width; mobile uses one page scroll and wrapping command links. Search results span all purposes; choosing a purpose clears search. Examples fill the terminal without executing. Each command includes a suggested inspection command and what to look for. These descriptions are reference material, not live results.

Use existing frontend-standards, product-design-quality and Impeccable guidance. The installed Taste payload targets marketing surfaces; current upstream also offers a separate app-screen workflow. No additional overlapping skill or animation dependency was needed. Native CSS transitions take 140–180ms and respect reduced motion. Retain the selected theme, 5px square scrollbars and native Git behavior.

Research: [Primer underline navigation](https://primer.style/product/components/underline-nav/) supports navigation between related views; [NN/g progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/) supports keeping secondary detail available without displaying everything at once; [NN/g menu design](https://www.nngroup.com/articles/menu-design/) supports visible navigation and clear current location. The official [Impeccable](https://github.com/pbakaus/impeccable) and [Taste Skill](https://github.com/Leonxlnx/taste-skill) sources were reviewed before choosing the installed guidance. These principles inform the design; learner preference and learning effectiveness still need direct testing.

Council follow-up: retain this structure and selected theme. Availability is plain text; View examples is a genuine control that moves focus to the examples without changing route or executing. Keep tablet visual order consistent with source order. Search announces counts and identifies the retained detail without automatically selecting a result; typing does not rebuild or animate that detail. Save shortcuts operate only while Workspace is visible. Placeholder text uses the theme's muted foreground for readable contrast. See DESIGN_REVIEW.md for the source comparison and council decision.

## Optional workspace comparison

Compare in the existing sidebar opens a read-only drawer. It compares the same selected branch's native ref across You, Sam and Shared, separately from each person's remembered origin ref. Commit messages and IDs come from the existing inspected state; missing/truncated details are labelled instead of inferred. Different IDs do not establish ancestry. Uncommitted work is explicitly associated with each person's current checkout; browser drafts are separate.

Keep the main workspace free of permanent comparison panels. The drawer uses the selected square charcoal/amber theme and thin scrollbars, a semantic table with a focusable horizontal scroll region on small screens, a short explanation and optional usage disclosure. Opening it sends no requests and executes no commands. Close/Escape returns focus to Compare; underlying editor/terminal controls are inert while covered, and route/panel changes restore them. Existing reduced-motion guidance applies. This is the only new feature in this increment; contextual coaching, persistence and additional experiments remain deferred.
