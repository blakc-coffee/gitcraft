# Try an unfamiliar task in ordinary Git

This is a formative assessment guide for the two-exercise prototype. It does not cover the full planned curriculum.

## Setup, separate from the assessment

Use a new, disposable folder on your own computer. You need ordinary Git, an editor and a terminal. A facilitator should prepare a small text repository with a `main` branch, clone it into two independent folders, and configure one new local bare repository as their common origin. Use local fictional identities only; no GitHub account, credentials or existing project is needed.

The project is a library notice, not the community event used in the browser. It has `hours.md` and `directions.md`. Both clones initially contain a 09:00 opening time and an entrance note awaiting confirmation. A facilitator publishes a valid ramp-access direction from the second clone after the learner has made their own local opening-time commit. Do not reveal that clone's files or command history during assessment.

The setup commands are deliberately outside the learner's task. If there is no facilitator, use the browser exercise as preparation and arrange the two-clone fixture before evaluating yourself; that attempt is self-practice, not a blind assessment.

## Task given to the learner

Change the library opening time to 09:30 and publish the correction. Preserve any contributor update you encounter. Before making your final commit, deliberately create a staged version that differs from your working file, then inspect and correct the discrepancy. Finish with the intended project content, no unintended local edits, and the shared branch updated.

Use normal Git and an editor. You may consult documentation. Do not use the browser observer, exact-command hints, or the lab restore button. If you need a facilitator's command recipe, record a supported attempt and try a changed task later.

## Evidence to explain

- Which content was working, staged and committed at the discrepancy?
- What did your clone know before and after communicating with origin?
- Why did a push succeed or fail, and how did you establish that?
- How did you verify both your correction and the contributor's valid work survived?

The facilitator checks actual content, clean state, retained contributor history and remote result. Score diagnosis, intentional commits, integration/sharing, recovery, and explanation from 0–2 each. A provisional independent pass is 8/10 with no required work lost. Report setup difficulties separately; do not penalize documentation lookup or slower typing. Repeat with different names/content after seven days before claiming retention.
